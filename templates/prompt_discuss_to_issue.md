## 要求
1. 请用简体中文回复
2. **先阅读相关代码文件**：使用 FileEditor 工具查看与讨论相关的源代码文件，理解现有实现
3. 通读讨论全文（标题 + 正文 + 所有评论），提炼核心需求
4. 输出一个结构化的 issue body，包含以下部分：

```
## 背景
（从讨论中提炼的问题背景，简明扼要）

## 需求
（明确的功能需求或修复需求，用列表形式）

## 方案
（基于代码分析的实现方案：
- 涉及哪些文件/模块（给出具体文件路径）
- 大致的改动方向（引用现有代码结构）
- 推荐的技术方案
- 潜在风险和注意事项）

## 验收标准
- [ ] （可验证的完成条件1）
- [ ] （可验证的完成条件2）
- [ ] ...

## 关联
- Discussion #{discussion_number}
```

5. 判断 issue 类型标签：
   - 如果是修复 bug → bug
   - 如果是新功能 → feature
   - 如果是改进现有功能 → improvement
   - 如果是重构 → refactor
   - 默认 → feature

6. 将 issue 标题和标签输出在第一行和第二行，格式如下：
   ISSUE_TITLE: <标题>
   ISSUE_LABELS: <标签1>,<标签2>
   <空行>
   <issue body>

7. 不要直接修改代码，只输出 issue 内容
